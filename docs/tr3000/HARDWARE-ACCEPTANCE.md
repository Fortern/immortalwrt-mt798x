# 实机验收清单（本轮全部待执行）

编译成功不代表无线稳定。只有下列实机项目另行完成后，才可把候选固件标记为稳定版本。
本轮没有刷写设备，也没有执行本清单中的操作。

## 验收记录

记录设备完整型号、硬件版本、源码提交、固件 SHA-256、测试日期、终端型号、
上游 AP 型号与版本、工作频段、信道、带宽、加密方式和网络连接图。
先确认测试镜像的兼容标识为 `cudy,tr3000-256mb-v1`，并准备经过确认的恢复途径。
升级与恢复流程本身也需要独立验收；不要把有构建产物理解为已验证可以安全升级。

## 证据与故障定位

每组测试记录开始/结束时间及通过条件，至少保存系统信息、接口/路由状态、
`logread`、`dmesg`、iwinfo 状态和流量测试结果。发生异常时优先保存当时日志，
再执行无线重载或重启；如存在 pstore，也保留其原始内容和时间。

区分“短时中断后自动恢复”和“MCU 超时、复位失败、panic、需人工恢复”。
不要只凭低速率显示判断驱动崩溃，也不要把单次吞吐测试通过视为长期稳定。
同一阶段只改变一个主要条件，先通过有线 WAN 与双频 AP，再引入 STA 回程及 AP/STA 共存，
这样出现问题时能追踪到新增的路径。

## 标记稳定版本的条件

所有必需项目有对应证据，无未解释的驱动崩溃或不可恢复中断，且升级/恢复验证完成。
验收结果绑定具体源码提交和固件校验值，不能自动推广到未来版本、其他硬件或新的配置组合。
