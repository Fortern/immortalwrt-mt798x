# 适配约束与源码核对记录

## 基线与范围

以 `v25.12.2` 为基线，保留 Linux 6.12 与正式版固定 feeds。
厂商参考版本见 `STATUS.md`。以下记录是源码检查结果，不代表运行验证通过。

## 已发现的集成要求

1. `mt_wifi` 构建依赖 `warp`，模块依赖 `conninfra`、`mediatek_hnat` 与 `wifi-dats`。
2. 厂商 HNAT 导出 `ra_sw_nat_hook_tx` 等接口；参考内核以太网驱动还导出
   `ppd_dev` 与 `eth1_in_br`。移植必须核对接口的执行语义与对象生命周期，不能只增加空桩消除链接错误。
3. 厂商设备树使用 `mediatek,wbsys`、`mediatek,mt7981-consys` 及 WOCPU 节点。
   板载 mt76 节点与厂商节点不能同时驱动同一硬件。
4. MT7981 的 `l1profile.dat` 使用 EEPROM 偏移 `0x0`、长度 `0x5000`。
   驱动按名称读取 `Factory` 分区；目标专用的隐藏配置默认值将编译偏移设为 `0x0`，
   展开配置检查会拒绝其他偏移。保留正式版分区写保护，MTD 写入辅助函数尊重该保护。
   MT7981 闪存校准芯片标识无效时初始化失败，避免通用默认 EEPROM 回退和随机 MAC。
5. `mtwifi-cfg` 提供 netifd AP、STA 配置接口；不需要为了基本 AP/STA 功能默认安装 WAPP。
6. 来源 LuCI 包通过首次启动脚本替换整个官方 `wireless.js`。本移植改为独立的
   `网络 → MediaTek Wireless` 入口，视图文件为 `view/network/mtwifi.js`，
   不覆盖官方无线页和通用网络模型。
7. 来源无线检测脚本默认开启无加密 AP。本移植生成默认禁用的无线配置，
   由用户设置 SSID、加密和所在地区后启用。

## Linux 6.12 集成边界

内核补丁按职责拆分为构建入口、数据包路径、复位握手三组。
以太网基础驱动仍采用正式版代码；厂商 HNAT 启用时排除上游 WED/PPE 硬件管理，
保留正式版其他以太网修复。TX/RX 的厂商描述符元数据与转发设备选择在该配置下生效。
转发设备缓存持有 netdev 引用；接口变化时更新引用，避免保存已释放设备指针。

厂商 HNAT 原有的私有 netdevice 路径接口改用 Linux 的 `dev_fill_forward_path()`。
本次处理 Ethernet、VLAN、PPPoE 路径；未支持的复杂路径留给软件转发，
不宣称完成其他交换机或 DSA 设备的加速适配。TR3000 的默认 LAN 为 `eth1`、WAN 为 `eth0`。

无线总线辅助代码保留设备资源和总线生命周期，修复探测成功后错误返回及临时资源悬空问题。
Wireless Extensions 由厂商集成的 Kconfig 显式选择；只在配置片段写入隐藏选项不能使其生效。
conninfra、warp 平台卸载回调、头文件和指针类型按 6.12 接口调整。
包版本使用 APK 能接受的格式，来源提交仍以来源记录为准。

## 无线配置链路

UCI `wireless` → netifd `mtwifi` 后端 → Lua 配置转换 → 厂商 dat 文件与 iwpriv → 驱动。
状态读取由局部新增的 iwinfo MTK 后端提供；保留原有 iwinfo 公共结构 ABI 和其他后端。
Lua 解释器、nixio、cjson、datconf 作为显式运行依赖安装。
双频共享模块重载时直接恢复另一频段原有接口，避免持锁递归执行另一轮无线启动。

默认不安装 WAPP/EasyMesh 服务，不启用自动频段引导。
参考配置中的 MBO 和 WAPP 管理的 MSCS/DABS QoS 扩展也不选用；
它们依赖 WAPP 事件接口，不是基础 AP、STA 或普通 WMM 队列的依赖。
APCLI、DBDC、HNAT、warp 与固定的 MT7981 无线/WO 固件组合保持启用。
配置检查会在展开配置与这些约束不一致时中止构建。

厂商默认 EEPROM 文件随来源保留，但不能替代本机 Factory 校准数据。
以太网 MAC 继续由正式版设备树的 bdinfo 来源读取；无线地址来自设备校准 EEPROM。
最终地址、频段对应关系及校准有效性属于实机验收项目。
不承诺直接恢复第三方固件配置备份，应先通过 UCI/界面重新建立配置。

## 版本与产物

构建目录位于 WSL Linux 文件系统，F 盘目录是唯一源码维护入口。
只同步已经提交的源码；编译配置、feeds 提交、构建环境、日志和最终软件包清单均需随产物保存。
代理地址只通过本机环境变量传入，不作为固件配置或通用构建脚本的硬编码依赖。

## 实机验收（本轮不执行）

- 正常启动，设备型号、分区布局、MAC 与校准数据来源正确。
- 有线端口、DHCP、DNS、IPv4/IPv6 路由正常。
- 双频 AP 接入、保存配置、重启与无线重载正常。
- STA 回程、AP/STA 共存、上游断开与恢复后自动重连。
- 有线与无线双向持续流量，反复终端重连，无异常重启、panic 或持续内存增长。
- 加速路径与基础转发一致，升级和恢复流程另行验证。
